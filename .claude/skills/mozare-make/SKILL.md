# Mozare Make

## Start from the artifact contract

Identify:

- what is being made;
- who/what will experience or use it;
- material/input constraints;
- accepted decisions;
- what can change;
- what must remain invariant;
- how the result will be inspected/tested.

## Make concretely

Avoid substituting keyword clusters, theoretical naming, or abstract process descriptions for actual design/material decisions.

For interactive/artistic work, specify or implement:

- objects/materials;
- spatial/temporal behavior;
- sequences and transitions;
- interface affordances;
- sensory surface where relevant;
- constraints/rules;
- failure/edge behavior;
- inspectable output.

## Keep layers distinct

A work is not its statement, rationale, implementation log, or construction instrument. Return each as a separate artifact/ref when multiple layers are required.

## Completion

Do not call a prototype complete because documentation describes intended behavior. Inspect/test the actual artifact where possible and record evidence.
