# Candidate Finalization Checklist

A fresh independent QA context must verify this list against one unchanged commit.

1. **Identity:** exact commit/build is recorded; tracked tree is clean; every completed DAG task has a schema-valid handoff and observed named-test evidence.
2. **Safety:** canonical reconstruction, stale proposal, transaction rollback, path/symlink, command injection, secret exclusion, preview sandbox, process stop, and loopback gates pass.
3. **Experience:** Focus/Field/Flow/Review/Output, system-first technical disclosure, responsive matrix, keyboard/focus, reduced motion, 200% zoom, and Persian/English bidi gates pass.
4. **Agent economy:** fake lifecycle, at least one available real adapter smoke, ContextCompiler/capsule/delta/routing/telemetry, OpenUI bounds/fallback, and proposal-only generated actions pass without whole-project prompt loading.
5. **Release boundary:** Windows launcher/recovery and real Mozare project pilot have truthful evidence; `RELEASE_REPORT.md`, `IMPLEMENTATION_HANDOFF.json`, `KNOWN_LIMITS.md`, and the evidence index bind to the same candidate. Verdict is only `CANDIDATE_READY_FOR_REVIEW` or `NOT_READY` until Mozare explicitly accepts it.
